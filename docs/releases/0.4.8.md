# DeckyCache 0.4.8

Choose whether cache covers entire selected drives or specific folders. Installation and update writes no longer allocate new cache blocks, and the final **Other cached data** tile explains occupancy outside the game list.

## Compatibility

**SteamOS Stable only.** Beta, Preview and Main are not supported.

| Requirement | This release |
| --- | --- |
| Tested SteamOS PC | 3.8.28, build 20260922.1, NVIDIA x86-64 |
| Required kernel | `6.18.50-valve2-1-neptune-618-gc7289a96b14d` |
| Library filesystem | Separate ext4 data partitions |
| Tested Decky Loader | 3.2.10 |

The kernel bundle is unchanged from 0.4.7. No kernel rebuild or on-device compilation is required.

## Changes

- **Cache scope:** choose **Entire selected drives** or **Selected folders**. Add Steam libraries or browse for folders across enabled drives.
- **Write-around:** copying, installation and Steam update writes go to the original HDD without allocating new cache blocks. Cached overlaps remain coherent.
- **Other cached data:** always the last tile, using the disk-and-rocket icon. It accounts for blocks outside the current game list without counting Small fragments twice.
- **Folder controls:** added spacing between selected folders and the Add folder action.
- **Preservation:** changing scope does not remount libraries or clear existing cache. Compatible built-in plugin updates retain the mounted cache and tracking IDs.

## What the scope choice means

Folder mode controls read admission, not whether a game is running. Reading selected files for copying, unpacking or verification can still populate cache.
Some direct or asynchronous reads cannot be assigned to a directory and bypass cache in folder mode.
The engine has 32 class slots per volume, shared by game tracking and selected folder roots. A new folder is refused if no required slot remains.

Previously cached data is retained. A large Other cached data tile can include data saved by older versions.
Use **Clear cache** if you want to discard all cached copies; the games on the HDD and the prepared SSD filesystem remain intact.

## Install or update

Download the attached **DeckyCache plugin ZIP**, not the source-code archive.
Enable Developer mode in Decky settings and use **Install Plugin from ZIP File** or **Install Plugin from URL**.

For an existing installation with the current updater, close games and finish Steam downloads, then use **Check for updates** in DeckyCache.
Confirm Decky's installer; the plugin reloads automatically.
Cache preservation requires the compatible built-in updater. The old updater in 0.4.5 or earlier and manual ZIP replacement can rebuild cache once.

## Validation

A native Decky update to the development build preserved occupied cache bytes, the library mount and all 31 installed Steam game entries.
Folder selection applied online without remounting or clearing cache. Isolated ext4 checks covered write admission, selected/excluded reads, cache hits, overwrites and atomic replacement.

After a normal PC restart, a 90-second MOUSE loading/gameplay observation measured **1.05 GiB from cache and 69 MiB from HDD**.
Approximately **94% of the measured storage-read bytes came from cache**, with matching physical NVMe reads and zero cache errors.
This confirms retained cache and real NVMe reads for that sample. It is not a loading-time benchmark or a measurement of RAM reads.

A real Steam download/update was not run for this release; file-update coherence was checked with controlled writes.
